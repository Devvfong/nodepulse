# ADR 001: Adoption of C++20 Standard

## Status
Accepted

## Date
2026-10-06

## Context
NodePulse is designed as a production-grade Linux server monitoring and management agent. It requires direct low-level interactions with the Linux kernel virtual filesystems (`/proc`, `/sys`) and POSIX system calls, alongside high-throughput, non-blocking asynchronous networking.

To achieve this, the project requires a compiled language providing:
- Zero-cost abstractions and deterministic memory management (RAII).
- Modern type safety to eliminate common C-style memory bugs.
- Expressive standard library primitives for buffer slicing (`std::span`, `std::string_view`).
- Compile-time template constraints (concepts) for clean API boundaries.

## Decision
We standardize on ISO C++20 (`-std=c++20`) as the baseline language standard across all libraries, applications, and test suites in NodePulse.

## Consequences

### Positive
- **Buffer Safety & Zero-Copy Views**: `std::string_view` and `std::span` allow safe, non-allocating string and buffer parsing directly over kernel file descriptors.
- **Concepts**: Allows compile-time constraints on stream parsers and serializers, improving compiler error clarity.
- **Designated Initializers**: Enhances readability and safety when initializing configuration and domain structs.
- **Coroutines & Concurrency Primitives**: Lays the foundation for modern asynchronous task scheduling.

### Negative / Trade-Offs
- **Compiler Requirements**: Requires GCC 11+ or Clang 14+. Older enterprise Linux distributions (e.g. CentOS 7 or Debian 10) cannot compile NodePulse without newer toolchain packages (e.g. GCC Toolset).
- **Tooling Support**: Static analyzers and IDE plugins must support C++20 syntax.

## Alternatives Considered
- **C++17**: Broadly supported, but lacks `std::span`, concepts, and designated initializers, leading to more boilerplate and higher allocation overhead.
- **Rust**: Excellent safety guarantees, but the primary project goal includes demonstrating modern idiomatic C++ systems development and Drogon async patterns.
- **Go**: Fast development, but garbage collection pauses, larger runtime footprint (>40MB base), and lack of direct zero-overhead control over memory allocation.
